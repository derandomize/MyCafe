## 1. Общие сведения

### 1.1 Полное наименование и обозначение

Полное наименование: No-code платформа для ресторанов «MyCafe».

Условное обозначение: MyCafe.

Краткое наименование в настоящем ТЗ: Платформа, Система, Приложение.

### 1.2 Заказчик и Разработчик

Заказчик: определяется договором на разработку Платформы «MyCafe».

Разработчик (Исполнитель): определяется по итогам конкурсной процедуры/договора с Заказчиком.

Допускается привлечение соисполнителей по согласованию с Заказчиком.

#### 1.2.1 Требования к Исполнителю

Исполнитель должен:

- иметь опыт реализации сопоставимых по масштабу/нагрузке SaaS-платформ и мобильных приложений (подтверждение за последние 3 года);
- иметь необходимые лицензии/сертификаты (в т.ч. по ИБ, PCI DSS при приеме платежей, если применимо);
- обеспечить гарантийную поддержку не менее 12 месяцев;
- предоставить план внедрения с интеграциями и сайзингом инфраструктуры (без привязки к конкретному вендору);
- обеспечить обучение пользователей и передачу документации (пользовательской и технической);
- соблюдать требования ИБ и законодательства о персональных данных.

### 1.3 Основание для разработки

- Договор между Заказчиком и Исполнителем.
- Внутренние стандарты Заказчика по ИБ.
- ГОСТ 34 серия (34.602, 34.603), ISO/IEC 27001, ISO/IEC 27002, OWASP ASVS/MASVS.
- Требования PCI DSS при обработке платежных данных (если платежи проходят на стороне Платформы).
- Регламенты магазинов App Store/Google Play для публикации мобильных приложений.

### 1.4 Сроки

Начало работ — по подписанию договора.

Общий срок создания первой версии (MVP) — не более 3 месяцев, полный релиз с интеграциями — до 6 месяцев, если не оговорено иначе договором.

### 1.5 Порядок оформления и предъявления результатов

Коммерческое предложение содержит детальный план-график работ, ресурсы, сроки, стоимость, поэтапность функционала.

По завершению этапов — акты выполненных работ, отчеты, демонстрации, развертывание на тестовых/прод средах.

Приемка проводится на основании Программы и методики испытаний и перечня документов раздела 8.

## 2. Назначение и цели создания Платформы

### 2.1 Назначение

«MyCafe» — мультиарендная no-code платформа для ресторанов, позволяющая:

- выпускать брендированные клиентские приложения (iOS/Android/Web) без программирования;
- управлять меню, заказами, бронированиями, программой лояльности, оплатами и аналитикой;
- автоматизировать работу персонала (официанты, кассиры, кухня, зал) и интегрироваться с внешними системами (POS, платежные шлюзы, CRM, доставочные сервисы).

### 2.2 Цели

- Сократить стоимость и срок выхода ресторана в мобильные каналы.
- Обеспечить единый цифровой контур: меню — заказ — оплата — доставка/самовывоз/к столу — лояльность — аналитика.
- Предоставить визуальные конструкторы (меню, экраны, бренд, промо, посадка столов).
- Обеспечить прозрачную систему скидок/кэшбэка/бонусов/промокодов.
- Предоставить API/интеграции для POS/CRM/доставок, шину событий, webhooks.
- Обеспечить масштабируемость и безопасность обработки заказов 24/7.

## 3. Характеристики объекта информатизации

### 3.1 Объект автоматизации

- Ресторанные сети и отдельные рестораны (рестораторы), их филиалы и зоны обслуживания.
- Персонал ресторана (официанты, кассиры, повара, менеджеры, администраторы).
- Посетители (клиенты).
- Партнеры-интеграторы (платежные провайдеры, доставочные сервисы, CRM/POS).

### 3.2 Текущее положение

- У большинства ресторанов отсутствует собственное качественное приложение/веб-канал.
- Фрагментация решений (меню, заказы, лояльность, оплата, аналитика) без единого контура.
- Высокие пороги стоимости и компетенций для запуска мобильных приложений.

## 4. Требования к Платформе

### 4.1 Общие требования

- Архитектура: трехуровневая клиент — сервер приложений — сервер БД; микросервисная/модульная; мультиарендность (multi-tenant).
- Единая централизованная БД/кластер БД с изоляцией данных арендаторов.
- Единый механизм аутентификации/авторизации (поддержка SSO OAuth 2.0/OIDC, JWT).
- Кроссплатформенность: Web (современные браузеры), iOS/Android (актуальные версии).
- Мультиязычность интерфейсов (минимум: русский, английский; по требованию: локализация).
- Масштабируемость по нагрузке (горизонтально), наблюдаемость (логирование, трассировка, метрики).
- Высокая доступность (целевой SLA 99.5%+ для производственной среды, без учета плановых работ).
- Соблюдение ИБ, защиту персональных данных, защиту платежных данных (при необходимости — PCI DSS SAQ A/A-EP).

Принципы:

- **Масштабируемость**: рост количества ресторанов, пользователей, заказов; поддержка x3 роста данных при наращивании мощностей.
- **Гибкость**: подключение новых модулей/интеграций без остановки сервиса.
- **Наблюдаемость**: audit trail, журналирование операций, мониторинг (APM, метрики).
- **Достоверность**: транзакционная целостность, идемпотентность платежей и вебхуков.
- **Стандартизация и совместимость**: REST/GraphQL API, webhooks, очереди/шина событий.

#### 4.1.1 Структура и функционирование

Подсистемы/модули:

**Обеспечивающие:**

- Модуль администрирования Платформы (суперадмин).
- Модуль ИБ (политики доступа, аудит, шифрование, KMS).
- Подсистема справочников и классификаторов (единицы измерения, валюты, языки, причины отмен, статусы).
- Шина обмена данными/очереди (event bus, webhooks, ретраи).
- Модуль биллинга арендаторов (тарифы, лимиты, платежи за подписку).
- Модуль управления сборками white-label приложений (генерация, подпись, публикация, конфигурации).
- Подсистема уведомлений (Push, Email, SMS, In-app).
- Подсистема аналитики и отчетности (OLAP/дашборды).
- Подсистема резервного копирования и восстановления.

**Функциональные (для Ресторатора и Клиентов):**

- Визуальный редактор меню и каталога (категории, блюда, модификаторы, комбо, фото/видео, allergens).
- Редактор брендинга и шаблонов интерфейсов (цвета, шрифты, логотип, стартовые экраны, баннеры).
- Управление филиалами, залами и картой столов (залы, столы, QR-коды, схемы).
- Заказы: доставка, самовывоз, к столу (QR-order), предзаказ, расписания, тайм-слоты.
- Бронирование столиков (ресурсное расписание, депозиты, no-show политика).
- Корзина, оплата, транзакции, фискализация/чеки (через интеграции).
- Программа лояльности (баллы, статусы, кэшбэк, промокоды, подарочные сертификаты).
- Управление промо-акциями и баннерами.
- Приложение Клиента (каталог/меню, поиск, фильтры, заказ, оплата, трекинг статуса, лояльность, отзывы).
- Приложение Сотрудника (официант/кассир/повар/менеджер зала): KDS, статусы заказов, закрытие чеков, пересадка столов, сплит счетов.
- Интеграции: платежные шлюзы, Push (Firebase/APNS), POS, CRM, службы доставки, карты/геокодинг.
- Панель мониторинга в реальном времени (очередь заказов, SLA кухни, средний чек, выручка).

##### 4.1.1.1 Назначение основных подсистем

- **Администрирование Платформы**: управление арендаторами, тарифами, лимитами, аудитом, доступом, конфигурацией интеграций по умолчанию.
- **ИБ**: политики паролей/2FA, RBAC/ABAC, шифрование PII в покое и в транзите (TLS 1.2+), контроль соответствия.
- **Справочники/классификаторы**: унификация данных и валидаторов.
- **Шина данных**: событийно-ориентированное взаимодействие между сервисами и внешними системами, гарантированная доставка, идемпотентность.
- **Отчеты и аналитика**: финансовые, операционные, маркетинговые, когортный анализ, удержание, LTV, NPS/оценки.
- **Генерация приложений**: конвейер сборки white-label iOS/Android/Web, управление сертификатами, профилями, bundleId/keystore.

##### 4.1.1.2 Режимы функционирования

- **Штатный режим** — 24/7.
- **Ограниченный режим** — при частичной недоступности внешних интеграций, работа в деградированном режиме (например, прием заказов без онлайн-оплаты).
- **Сервисный режим** — плановые работы по регламенту (с уведомлением).
- **Аварийный режим** — согласно плану реагирования на инциденты (IRP), с восстановлением из резервных копий при необходимости.

##### 4.1.1.3 Перспективы развития

- Маркетплейс плагинов/виджетов внутри Платформы.
- Собственный курьерский модуль и роутинг.
- Персонализация рекомендаций (ML).
- Программа партнерских кросс-акций между ресторанами.

#### 4.1.2 Пользователи и роли

Категории:

- Посетитель (Клиент).
- Ресторатор (владелец/администратор ресторана).
- Персонал ресторана: Официант, Кассир, Повар (KDS), Менеджер зала.
- Администратор Платформы (Super Admin).

Роли ресторатора (пример):

- **Владелец/Директор** (полный доступ в рамках арендатора).
- **Маркетолог** (брендинг, промо, лояльность, контент).
- **Операционный менеджер** (заказы, бронь, залы, смены).
- **Бухгалтер** (финансы, отчеты).
- **Тех. администратор** (интеграции, API ключи).

Численность пользователей не ограничивается; Платформа должна поддерживать рост до десятков тысяч клиентов в онлайне и тысяч заказов в час суммарно (масштабируется инфраструктурой).

#### 4.1.3 Требования к надежности

- Высокая доступность сервисов (кластеризация/автоскейлинг).
- Резервное копирование: ежедневные инкрементальные, еженедельные полные, хранение не менее 30 дней; тест восстановления не реже 1 раза в квартал.
- Устойчивость к сбоям: отказоустойчивые БД (репликация), очереди, кэш.
- Журналирование, алертинг, SLO/ошибки и латентность контролируются.
- Дозащита от ошибочных действий пользователей (подтверждения, soft delete, версии).

#### 4.1.4 Требования безопасности

- Аутентификация: email/телефон+пароль, соц. входы, 2FA (опционально).
- Авторизация: ролевая (RBAC), возможно атрибутивная (ABAC).
- Шифрование: TLS 1.2+, шифрование PII/секретов на хранении (KMS/HSM).
- Сегментация данных арендаторов; запрет утечек между арендаторами.
- Соответствие ISO/IEC 27001/27002; OWASP ASVS/MASVS; PCI DSS SAQ A при редиректе на платежного провайдера.
- Антифрод/скоринг по заказам (базовый), защита от бот-трафика (reCAPTCHA/ковенанты).
- Логи аудита (кто, что, когда изменил), неизменяемые журналы (WORM) по критичным операциям.

#### 4.1.5 Эргономика и техническая эстетика

- Единая дизайн-система (шрифты, цвета, компоненты).
- Минимизация действий в частых сценариях (оформление заказа ≤ 5 шагов).
- Доступность: контраст, размеры кликабельных зон, поддержка screen readers (по возможности).
- Подтверждения на удаление/важные операции, информативные сообщения об ошибках.

#### 4.1.6 Эксплуатация, обслуживание, хранение

- Регламенты обновлений, окна простой/degraded режима.
- Инструкции по резервному копированию/восстановлению, чек-листы.
- Обновления без простоя (blue/green, rolling), по возможности.

#### 4.1.7 Дополнительные требования

- Масштабируемые интерфейсы и БД.
- Возможность включения/выключения модулей на уровне арендатора.
- Встроенные подсказки/обучающие туры для пользователей.

### 4.2 Требования к функциям

#### Обеспечивающие модули

**Администрирование Платформы:**

- Управление арендаторами (создание, тариф, лимиты, статусы).
- Управление пользователями и ролями (RBAC), SSO настройка.
- Управление конфигурациями интеграций по умолчанию.
- Мониторинг сервисов, очередей, статусов сборок приложений.
- Аудит действий, журнал событий, экспорт логов.
- Управление биллингом арендаторов (подписки, инвойсы, платежи).

**Информационная безопасность:**

- Политики паролей, MFA, сессии, блокировки по брутфорсу.
- Управление ключами API, ротация секретов.
- Контроль доступа к данным (тенант-изоляция).
- Политики хранения и удаления персональных данных.

**Справочники/классификаторы:**

- Валюты, единицы измерения, НДС/налоги, типы модификаторов.
- География (страны, города, зоны доставки).
- Причины отмен, статусы заказов и бронирований.

**Шина обмена данными:**

- Публикация событий (OrderCreated, PaymentSucceeded, ReservationNoShow и пр.).
- Подписки внутренних микросервисов и внешних webhooks.
- Ретраи, дедупликация, идемпотентность.

**Уведомления:**

- Шаблоны и локализация (email/SMS/push/in-app).
- Триггеры и расписания, напоминания (бронь, статус, промо).

#### Функциональные модули (тенант — Ресторан/Сеть)

**Визуальный редактор меню:**

- Категории, блюда, описания, алергены, фото/видео.
- Модификаторы (обязательные/необязательные), наборы допов, варианты.
- Комбо/сет-меню, рекомендации, теги (веган, острое и пр.).
- Мультискладские цены/налоги/валюта, расписания доступности.

**Брендинг и шаблоны:**

- Логотип, цвета, шрифты, иконки.
- Настройка экранов: главный, каталог, баннеры, блоки.
- Домен/поддомен для WebApp, bundleId/packageName для мобильных.

**Управление филиалами и залами:**

- Филиалы, часы работы, адреса, зоны доставки (по радиусу/полигонам).
- Залы/столы (схема, QR-коды), статусы столов, объединение/пересадка.

**Заказы:**

- Каналы: доставка, самовывоз, к столу (QR-order), предзаказ.
- Процессинг: создание, подтверждение, оплата, KDS, выдача/доставка, закрытие.
- Таймслоты, ограничения по кухне/пиковым часам.
- Отмена/возврат по политике, частичный рефанд (если поддерживает провайдер).
- Чеки/фискализация через интеграции (там, где требуется законом).

**Бронирование:**

- Создание/подтверждение/отмена, депозиты, no-show.
- Привязка к столам, SLA, напоминания.

**Оплата:**

- Интеграция с платежными шлюзами (карты, Apple Pay/Google Pay, локальные).
- 3DS, сохранение токенов карт у провайдера (PCI DSS responsibility shift).
- Webhooks статусов платежей, обработка отказов/ретраев.

**Лояльность и промо:**

- Баллы, уровни, правила начисления/списания, кэшбэк.
- Промокоды (разовые/многоразовые, персональные/публичные), подарочные сертификаты.
- Лимиты, стекируемость, исключения по меню/категориям.

**Приложение клиента (iOS/Android/Web):**

- Регистрация/вход, профиль, адреса, способы оплаты (токены у провайдера).
- Каталог/поиск/фильтры, карточка блюда, корзина.
- Оформление заказа, выбор способа получения и времени.
- Трекинг статуса, чат/коммуникации (опционально), отзывы/оценки.
- Экран лояльности, история заказов, статус уровня.

**Приложение сотрудника (iOS/Android):**

- Авторизация персонала, роли.
- KDS: лента заказов, статусы (принят/готовится/готов/выдан).
- Официант/кассир: открытие/закрытие счета, сплит, печать, инкассация (через POS интеграцию).
- Карта столов: посадка/пересадка/объединение.
- Уведомления о новых заказах, SLA кухни.

**Аналитика/отчеты:**

- Продажи (по филиалам/категориям/блюдам/часам), средний чек, конверсия.
- Заказы (SLA, отмены, причины, источники).
- Лояльность (начисления/списания, возвраты, удержание).
- Эффективность промо, RFM, когортный анализ.
- Экспорт (CSV/XLSX), API для BI.

**Интеграции:**

- Платежные шлюзы.
- Push (Firebase/APNS), SMS, email.
- POS/CRM/ERP (двунаправленно), доставочные платформы (через коннекторы).
- Карты/геокодинг/расчет расстояний.
- Фискальные регистраторы/онлайн-кассы (в странах, где требуется).

- **Промо**: промокоды, правила применения, бюджеты, периоды.

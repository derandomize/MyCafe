# План тестирования проекта "MyCafe"

## 1. Объект тестирования (Что тестируем)

Тестированию подлежит No-code платформа "MyCafe" в конфигурации MVP.

### 1.1. Компоненты системы
1.  **Backend API:**
    *   Модули: Аутентификация, Меню, Заказы, Бронирование, Лояльность.
    *   Интеграции: Платежные шлюзы, Push-уведомления.
2.  **Панель управления Владельца (Web):**
    *   Редакторы меню и брендинга.
    *   Дашборды аналитики.
3.  **Клиентское приложение (Mobile/Web):**
    *   Каталог, Корзина, Чекаут, Личный кабинет.
4.  **Приложение для сотрудников (Mobile):**
    *   Обработка заказов, Карта столов (KDS).

---

## 2. Окружение и совместимость

### 2.1. Поддерживаемые платформы (Клиентская часть)
*   **Мобильные устройства:**
    *   **iOS:** Версия 14.0 и выше (iPhone 8 и новее).
    *   **Android:** Версия 10.0 и выше (API Level 29+).
*   **Веб-браузеры (Desktop & Mobile):**
    *   Google Chrome (последние 2 версии).
    *   Safari (последние 2 версии).
    *   Yandex Browser (последние 2 версии).
    *   Firefox, Edge (последние 2 версии).

### 2.2. Серверное окружение
*   **Staging (Тестовый стенд):** Полная копия продакшн-среды с ограниченными ресурсами.
*   **Базы данных:** PostgreSQL 14+, Redis 7+.
*   **Сетевые условия:** Тестирование при стабильном Wi-Fi, 4G, а также эмуляция нестабильного соединения (3G, Packet Loss).

---

## 3. Типы проверяемых ошибок

1.  **Функциональные ошибки:** Несоответствие бизнес-логики требованиям SRS (неверный расчет скидок, ошибки в статусах заказов).
2.  **Ошибки интерфейса (UI/UX):** "Поехавшая" верстка, нечитаемый текст, нерабочие кнопки, нарушение гайдлайнов платформ.
3.  **Ошибки валидации:** Отсутствие проверки обязательных полей, некорректная обработка спецсимволов, SQL-инъекции (базовые).
4.  **Ошибки интеграции:** Некорректная передача данных между Backend и внешними сервисами (платежи, карты).
5.  **Ошибки производительности:** Время отклика API > 800мс, зависание интерфейса при скролле меню (100+ позиций).
6.  **Критические сбои:** Падение приложения (Crash), зависание сервера (500 Internal Server Error).

## 4. Методы и инструменты тестирования

| Метод | Описание | Инструменты | Ответственный |
| :--- | :--- | :--- | :--- |
| **Unit-тестирование** | Проверка отдельных модулей и функций кода. | Jest, PyTest | Разработчики |
| **Интеграционное** | Проверка взаимодействия API и микросервисов. | Postman, Newman | QA Automation |
| **Ручное функциональное** | Проверка сценариев использования (Use Cases). | TestRail (кейсы) | QA Manual |
| **UI/UX тестирование** | Сверка с макетами Figma, проверка адаптивности. | BrowserStack, Figma | QA Manual, Дизайнер |
| **Регрессионное** | Проверка отсутствия деградации после обновлений. | Cypress (Web), Appium | QA Automation |
| **Нагрузочное** | Проверка стабильности при 1000 RPS. | JMeter, K6 | DevOps / QA |

## 5. Условия прекращения и возобновления тестирования

### 5.1. Условия приостановки (Stop Criteria)
Тестирование приостанавливается, если:
1.  Обнаружен **Блокирующий дефект (Blocker)**, препятствующий выполнению основного сценария (например, невозможно авторизоваться или создать заказ).
2.  Недоступность тестового окружения (Staging) более 2 часов.
3.  Количество дефектов критического приоритета (Critical) превышает 5 штук.

### 5.2. Условия возобновления (Resumption Criteria)
Тестирование возобновляется после:
1.  Устранения всех блокирующих дефектов и подтверждения фикса (Smoke Test).
2.  Восстановления работоспособности тестового стенда.

### 5.3. Условия завершения (Exit Criteria)
Тестирование считается завершенным для релиза, если:
1.  Выполнены 100% тест-кейсов из плана релиза.
2.  Отсутствуют открытые дефекты с приоритетом Blocker, Critical, High.
3.  Успешно пройден полный цикл регрессионного тестирования.

## 6. Оценка трудоемкости и календарный план

**Ресурсы:** 2 QA-инженера (1 Manual + 1 Automation/Lead).
**Общий объем:** ~320 человеко-часов (на этап MVP).

| Этап тестирования | Сроки (Недели проекта) | Трудоемкость (ч/ч) | Описание работ |
| :--- | :--- | :--- | :--- |
| **1. Подготовка** | Недели 2-3 | 40 | Анализ требований, написание тест-плана и чек-листов. Настройка тестового окружения. |
| **2. Тестирование API** | Недели 4-6 | 80 | Тестирование эндпоинтов Backend (Auth, Menu, Order). Автоматизация смоук-тестов API. |
| **3. Тестирование Web** | Недели 7-9 | 80 | Функциональное и UI тестирование Панели управления. Кросс-браузерное тестирование. |
| **4. Тестирование Mobile** | Недели 9-11 | 80 | Ручное тестирование приложений iOS/Android. Проверка на реальных устройствах. |
| **5. Приемочное и Регресс** | Неделя 12 | 40 | Полный прогон регрессионных тестов перед релизом. Нагрузочное тестирование. |

**Итого:** Тестирование интегрировано в спринты разработки и идет параллельно с написанием кода (Shift-Left Testing), с финальной фазой стабилизации перед релизом.
